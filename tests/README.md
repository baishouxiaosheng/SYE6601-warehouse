# 测试组 B：建链评测与回归实验最终报告 (60 例全量)

## 1. 实验概述
本实验旨在验证企业故障补偿审核系统中“自动建链”与“人工预配置”两种机制的有效性。我们使用 Qwen-7B-Instruct 模型，对 60 条运行侧案例进行了全量跑测，并记录了模型的原始推理过程与结论。

- **模型**: Qwen/Qwen2.5-7B-Instruct (通过 SiliconFlow API 调用)
- **自动建链组 (Auto Chain)**: 模型仅接收原始证据状态，依靠 Prompt 中的“铁律”进行自主推理。
- **人工预配置组 (Manual Config)**: 在 Prompt 中显式注入业务规则（如“遇 NOT_FOUND 判 REFUTE”）。

## 2. 核心数据分析

### 2.1 自动建链组 (Auto Chain) 表现
- **特点**：极度保守，安全性高。
- **数据**：在 60 条案例中，模型输出了大量的 `UNKNOWN` (转人工)。这主要归功于 Prompt 中设定的“异常阻断铁律”（如遇到 TIMEOUT, NOT_FOUND, pagination_complete=false 等直接阻断）。
- **优点**：有效避免了在证据缺失或系统故障时的“强行裁决”，符合企业级应用对安全性的要求。

### 2.2 人工预配置组 (Manual Config) 表现
- **特点**：决策果断，但错误率较高。
- **数据**：模型倾向于输出 `REFUTE` (不补偿) 或 `SUPPORT` (补偿)，`UNKNOWN` 比例大幅下降。
- **缺点**：由于规则注入过于简单，模型在处理复杂免责条款和数值比较时出现了大量“幻觉”和逻辑错误。

## 3. 典型失败案例归因 (Failure Analysis)

通过对 60 条结果的逐一核查，我们发现了小参数模型在数值推理和规则理解上的典型缺陷。以下是核心失败案例：

### 🔴 案例 A-014 / A-042：数值比较逻辑反向 (Auto Chain)
- **场景**：通用客户故障 65 分钟 (门槛 >=60 分钟)。
- **模型输出**：`REFUTE` (不补偿)。
- **模型理由**：“故障时长为 65 分钟，超过了 60 分钟的时长门槛，因此不符合赔偿条件。”
- **归因**：模型将“超过门槛”理解为“超出允许范围”，而非“满足最低要求”。这是典型的**业务语义理解错误**。

### 🔴 案例 A-017：单位幻觉 (Auto Chain)
- **场景**：KA 客户故障 15 分钟 (门槛 >=10 分钟)。
- **模型输出**：`REFUTE`。
- **模型理由**：“KA 客户的时长门槛是≥10 小时。故障时长为 15 分钟...不满足时长门槛。”
- **归因**：模型凭空将“10 分钟” hallucination 为“10 小时”，导致结论完全错误。

### 🔴 案例 A-049 (DYN-01 主案例)：关键词强行匹配幻觉 (Auto Chain)
- **场景**：合同要求 24h 内提交工单，实际 20h 提交 (满足条件)。
- **模型输出**：`UNKNOWN` (转人工)。
- **模型理由**：“证据状态中包含'TIMEOUT'关键词（实际提交工单时间超过 24 小时）...”
- **归因**：模型为了触发“异常阻断铁律”，强行将“20 小时”曲解为“TIMEOUT”。这证明了**简单的关键词匹配规则容易被模型滥用**。

### 🔴 案例 A-043 / A-048：边界值逻辑精神分裂 (Auto Chain)
- **场景**：金融客户 14 分钟 (门槛 15)，VIP 客户 29 分钟 (门槛 30)。
- **模型输出**：均判为 `SUPPORT` (补偿)。
- **模型理由 (A-048)**：“差 1 分钟未达到 30 分钟门槛...因此满足赔偿条件。”
- **归因**：模型在 `reasoning` 中正确识别了“未达到”，但在 `status` 中却输出了“满足”。这是**逻辑推理与最终结论脱节**的典型表现。

### 🔴 案例 A-016 / A-058：免责条款误判 (Manual Config)
- **场景**：DDoS 攻击 / 计划内维护。
- **模型输出**：`SUPPORT` (补偿)。
- **归因**：在人工预配置模式下，模型忽略了具体的故障原因，仅根据“时长达标”就盲目判赔，说明**缺乏对优先级规则（免责 > 时长）的理解**。

## 4. DYN-01 自动建链专项验收

针对文档强制要求的 DYN-01 系列（合同新增“24h 内提交工单”条款），我们进行了重点验证：

- **A-050 (超时 30h)**: 模型正确输出 `REFUTE`，识别出 30 > 24。
- **A-051 (边界 24h)**: 模型正确输出 `SUPPORT`，识别出 24.0 <= 24。
- **A-052 (403 阻断)**: 模型正确输出 `UNKNOWN`，触发了权限阻断规则。
- **A-053 (跨页取证)**: 模型正确输出 `UNKNOWN`，识别出 `pagination_complete=false`。

**结论**：除了主案例 A-049 因关键词幻觉导致误判外，模型在 DYN-01 的配对案例中展现了良好的**结构增量识别能力**，能够根据合同新条款调整裁决逻辑。

## 5. 结论与工程建议

1. **小模型不可直接用于核心决策**：Qwen-7B 在数值比较（如 65 > 60）、单位换算（分钟变小时）和复杂逻辑（免责优先级）上存在严重缺陷。
2. **“自动建链 + 规则兜底”是最佳实践**：
   - 自动建链能够发现新材料中的隐含条件（如 DYN-01 的工单条款）。
   - 但必须配合**确定性的代码规则引擎**（而非仅靠 Prompt）来处理数值比较和异常阻断。
3. **置信度成绩单的必要性**：鉴于模型的高“转人工”率和偶发的逻辑幻觉，系统必须输出包含证据链缺口的“置信度成绩单”，以便人工快速复核。
