# 联调清单

## 先看什么

1. 02B：缺建和未审核关系怎么出现在快照里。0.2 不遍历模型自己生成的节点来发明必查。
2. 03A：非关键剪枝必须带 `loop` 或 `checker_b` 记录。没有记录时成绩单不会把它当成无关。
3. 08B：读 `examples/v2/*.scorecard.json`。等级和阻断放在设计分前面。证据不足时设计分是 null。
4. 01A / 产品经理：基础必查到底有哪些，仍见 `docs/03_待团队确认.md`。
5. 05A / 06B：图质量计数只进 `evaluate_runs` 的 0.2 记录，不进单例评分。

## 本地演示

在 `modules/confidence_a_mvp`：

```sh
python tools/run_demo.py
python -m confidence_a score examples/v2/01_missing_baseline.input.json --output outputs/missing_baseline.json
python -m confidence_a score examples/v2/06_dyn01_before_ticket.input.json --output outputs/dyn01_before.json
python -m confidence_a score examples/v2/07_dyn01_after_ticket.input.json --output outputs/dyn01_after.json
python -m confidence_a render outputs/dyn01_before.json --output outputs/dyn01_before.md
python -m confidence_a metrics examples/runs.v2.json --output outputs/metrics.v2.json
```

预期：

- 漏建专属合同必查时，其他节点即使全是 SUPPORT，等级也是「证据不足」，设计分不展示，原始设计分低于 100。
- 条款已发现但不能解释时，未展开计数大于 0，不叫条件已齐。
- 403 和分页未完不会因为多几条辅助证据而放开。
- 合同 REFUTE、其余门槛通过时，ineligible 可以是「已建模范围内证据充分」。
- 非关键剪枝显示「附保留说明」，流程状态保持上游的 completed。
- DYN-01 工单未取是关键缺口；取回后重算。两张卡的 `graph_version` 和 `answer_version` 各自一致，并且前后不同。说明文字来自结构变化记录，不是另一次模型判断。

0.1 的三个样例仍然是 100 / 100 / 49。49 只属于 0.1 演示上限。

## 可以发到群里的说明

07A 在原来的义务评分上增加了 0.2 建链风险成绩单。硬门槛先于分数，等级是「证据不足 / 附保留说明 / 已建模范围内证据充分」。漏建必查、未展开条款、未决关键关系、影响答案的范围不明，以及因此发生的 403、分页未完和预算停止，都会挡住确定建议，包括否定建议。

分数只表示已声明范围内的证据和过程质量，不表示图完整，也不是答案概率。离线指标增加了漏建率、错误接纳关系、关键缺口漏报、结构扩展路径和版本一致性；`+30%`、`<5%`、`-50%` 仍是拟验证目标。样例是合成数据。待确认项在 `docs/03_待团队确认.md`。
