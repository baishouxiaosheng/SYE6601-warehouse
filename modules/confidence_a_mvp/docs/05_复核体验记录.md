# 复核体验记录

这是记录表，不是已经做过的实验。不要把空表或演示成绩单填成满意度结果。

对照材料使用同一份冻结答案。比较三种视图：只有答案、答案加来源、答案加成绩单。不要让同一个人反复看同一个案例后再把速度提高当成界面效果。约 60 个合成业务案例不等于 60 个复核样本。

每个受试者、每个案例记录：

| 字段 | 记什么 |
|---|---|
| reviewer_id | 匿名编号。不在这里写姓名。 |
| case_id | 冻结案例 |
| view | answer / answer_plus_source / answer_plus_scorecard |
| answer_correct | 是否指出上游冻结的业务建议 |
| decisive_source_found | 是否指出决定性来源 |
| later_condition_found | 是否指出后来才出现的条件，例如 DYN-01 的 24 小时工单 |
| critical_gap_found | 是否指出关键缺口，而不是只看到已通过节点 |
| next_step_found | 是否指出下一步该核什么 |
| elapsed_ms | 用时。缺失则 null，不要估一个好看的数 |
| notes | 只记观察，不改成绩单状态 |

汇总时同时报告正确数、关键缺口识别数和用时，并说明人数、顺序和学习效应。只问「界面是否好看」或「是否满意」不够。

成绩单给的是已声明范围里的核对线索。图内节点都通过，也不等于发现了全部政策。
