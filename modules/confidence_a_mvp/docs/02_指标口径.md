# 指标口径

离线入口 `evaluate_runs(payload)` 按 `schema_version` 分派。线上 `score_snapshot` 不读这些记录，也不读 gold。

## 0.1 原有指标

分母和字段保持不变：终局正确率、确定回答正确率、无依据确定回答率、自动覆盖、自动成功、升级率、正确升级次数、失败运行，以及调用、费用、耗时的均值和缺测数。

分组键包含方法、对照、数据版本、规则版本、权限、执行方式、`fault_origin`、演示标记、费用单位、评审口径。自然错误和注入故障不会并进同一组。失败运行留在分母里。缺测成本保持 null。

`assertion_supported` 仍是独立评审对「这一次运行实际拿到的证据」的判断。不能用 score、gate 或 Checker 自述代替。

## 0.2 新增指标

0.2 运行记录在 0.1 字段之外增加 `graph_quality`。这些计数由 05/06 的离线标注提供。识别数不能大于标注数，错误接纳数不能大于已接纳关系数，漏报计算同样不允许分子超过分母。

| 字段 | 分子 / 分母 |
|---|---|
| critical_omission_rate | 标注的关键条件中未被运行识别的数量 / 标注的关键条件数 |
| accepted_wrong_relation_rate | 已接纳但标注为错误的关系 / 已接纳关系。已接纳数为 0 时 value 为 null，不是 0 |
| critical_gap_miss_rate | 标注存在但成绩单未报告的关键缺口 / 标注的关键缺口 |
| structure_expansion_path_success | 阶段全部成功的适用运行 / 声明有结构扩展路径的运行 |
| structure_expansion_stage_success | 成功阶段数 / 这些运行的应有阶段数 |
| answer_scorecard_version_consistency | 答案版本与成绩单答案版本一致，且图版本也一致的运行 / 全部运行 |

`path_applicable=false` 的运行不进入路径成功率分母，也不能把 0 个阶段填成成功。固定全查可以用这个标记表示「没有结构扩展路径」。

分组键与 0.1 相同，所以自然故障和注入故障仍然分开。0.2 报告额外带有：

- `measurement_status=NOT_A_MEASURED_RESULT`
- `target_status.status=PROPOSED_NOT_MEASURED`
- 三个目标 `+30%`、`<5%`、`-50%` 的 `measured` 固定为 null

这些目标只表示「拟验证」，不能写成已经测得的成绩或保证。演示文件 `examples/runs.v2.json` 是手写计数，用来核对公式。

正式数值要等 06 冻结同一分母、同一案例配对和同一故障分层之后再汇总。本模块不自动计算方法间增益。

## 复核体验

复核如果进行，记录的是正确性、关键缺口有没有被看出来、以及用时。满意度不能代替这三项。记录表在 `docs/05_复核体验记录.md`，当前没有样本，不能填演示数字充当结果。
