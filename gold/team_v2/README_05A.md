版本：2.0｜日期：2026年11月17日

## 交付范围

本包覆盖工业60条、保险60条，共120条模拟监控日志，包含751个命题判据：工业307个、保险444个。原始日志未修改。

每个命题包含回答原文、预期状态、证据字段、判定理由及必要的补证条件，供证据链、缺口识别、补证计划及置信度模块开展测试对照。

## 判定规则

| 状态 | 含义 |
|---|---|
| SUPPORT | 在明确的对象、时点、范围或假设下有证据支持 |
| REFUTE | 与适用字段或规则存在明确矛盾 |
| UNKNOWN | 证据不足，尚不能确定 |
| CONFLICT | 来源互相矛盾且没有足够的消解依据 |
| MISSING_RULE | 有读数或事实，但缺少适用判断规则 |

五类评测读取gold_status。仅支持四态的接口读取gold_status_four_state，将MISSING_RULE映射UNKNOWN，并在gap_type中保留缺规则原因。评测报告应注明状态口径。

正确读数不代表判断充分，抽样合格不代表每件合格，系统就绪不代表获得安全许可，初步估损不代表最终赔款。条件计算仅在明确假设下成立。超时、无记录或未完成不直接等于反面事实成立。

来源内部存在冲突时保留CONFLICT，不以程序输出或外部常识强行替换模拟日志。DECLARED_UNKNOWN描述回答的表达方式，证据状态仍针对底层事实。

## 接入pytest

1. 保留现有格式、图结构、来源定位及引用一致性测试。
2. 按原始run_id定位，依据命题内容及范围对齐系统输出，不按CLM编号硬配。pred_claim_id未预填，避免依赖特定版本的自动编号。
3. 处理合并命题、一对多及重叠原文的范围匹配；未抽取命题计入遗漏，不能从统计中默默剔除。
4. 分别记录状态判断、命题抽取、缺口识别和补证参数结果。answer_coverage表示原回答是否回应目标，不代表正确或充分。
5. review_status及来源元数据保留原值；正式验收按项目约定的审核门槛筛选，开发测试与正式验收成绩分别记录。
6. 工具协议未提供时保留tool=null，不虚构接口。真实执行回执到位后，再验证补证闭环。

## 校验结果与适用边界

已通过格式约束、60+60条运行唯一性、751个命题原文跨度、证据字段定位与原值一致性、缺口引用、严重标签一致性及源文件哈希校验。

本次交付不包含真实接口联调、真实Loop执行或系统准确率实测。标注来源、审核类型及当前状态见各JSON元数据；结构校验通过不等同于项目正式验收完成。高风险与严重问题标签按本包记录的口径使用，项目评分阈值以组内最终约定为准。
